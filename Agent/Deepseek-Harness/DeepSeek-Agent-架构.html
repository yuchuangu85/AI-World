Layered Architecture · Data Flow

八层结构：每一层干什么、怎么设计、往下传什么、往返回什么

对象是 DeepSeek 官方开源的 Agent 体系：DSH 底座（L1–L4，单会话执行内核 + 无特权插件树） 与 Super-agent 自治层（L5–L8，多会话调度 + 事件准入）。 下面三件事一次讲清：静态分层、动态走向、边界契约。

8 层 5 条典型链路 11 个边界契约 来源：公众号文章 + 两个 MIT 仓库 + 本机运行时抽查 生成于 2026-11-02
L1–L4 底座（DSH）：回答「一个 Agent 一次轮次怎么跑」 L5–L8 自治层（Super-agent）：回答「多任务/多事件/多会话怎么协调」

L8

信道与人机面

Channels & Human Surface自治层

Agent 的感官与嘴

作用

输入侧把 IM 群聊、GitHub Issue/PR 评论、CI 结果归一成事件；输出侧把结果按信道习惯表达。它决定了「人怎么感知到这个 Agent」。

设计取舍

  • 一个 Source = 事件流 + 写侧 Channel：kind 可复用，instance 是一份配置
  • 先把噪音挡在门外：Source 在进入领域前就丢掉 bot 自己的消息与不在收听范围的 Trigger
  • 不把终端交互搬进群聊：IM 走 100 词硬限、GitHub 走高密度结构化交付
  • 输出必须可恢复：所有外发消息经 Outbox，按 Ticket+会话保序、失败退避重试

↓ 下传（请求）

不可变 Trigger（含 actor、地址、Thread 归属、Source 自有 meta）；原始记录可回读（用于深度上下文）。

GitHub 侧是 60s 轮询，飞书侧是 live 事件消费 + 历史回填。

↑ 返回（响应）

回执 / 回答 / 结果 / attention 四类消息；发送结果是 sent / gone（会话没了）/ waiting（Source 离线）。

载荷形状 / 锚点 
Trigger {
  id, at,                 // 内容派生 id：sha256(JSON(values))[0:32]，天然幂等
  human,                  // 是人写的吗（决定能不能唤醒已结束工单）
  addressed,              // 'mention' | 'direct'，由 Source 声明
  threads: [threadKey],   // 一条 Trigger 可同时属于多个 Thread
  meta                    // Source 自有，核心不解释
}

L7

事件准入

Policy · Gate · Assessment · Mandate自治层

谁能让它干活，干多大

作用

把「高噪音、低触发率」的环境事件流筛成「值得开工的工作」，并给这份工作一个可审计的授权依据。它是文章里最轻、原型里最厚的一层。

设计取舍

  • 两段式：确定性 gate() 快筛（白名单 / 点名 / 准入表 / bot 名单），再交模型 assessment 慢判
  • 三种 accept mode：off / observe（默认，只记录「本来会做什么」）/ auto
  • 授权不可变：Mandate 三变——创建、人 stop、revalidate 失败吊销
  • 改规则不打断在办工作：Policy 版本变化只通知受影响的 Ticket，不强行取消

↓ 下传（请求）

Trigger 批 + Thread 快照 + 该 Thread 全部 Ticket（含已结束）+ 当前 Policy → 一次判定。

gate 先给「强度」（explicit / inferred / 拒绝码），assessment 再给「方向与范围」。

↑ 返回（响应）

Decision（accept / stop / ignore / unavailable + 原因码）与 Mandate（策略版本、范围、强度、准入依据）。

Decision 由 Router 通过批量路由真正「下单」，不是模型自由发挥。

载荷形状 / 锚点 
Decision { outcome: 'accept'|'stop'|'ignore'|'unavailable',
           reasons: [{ code, values[], triggerId? }], ticket? }

Mandate  { policyVersion, scope, strength: 'explicit'|'inferred',
           basis: { via: 'addressed'|'followup'|'admission'|'bot',
                    source, row, sender, rules[] } }

L6

自治调度：Router / Worker

Main Session ↔ Executor Sessions自治层

一层分派，一层干活

作用

把「维护全局连续性」与「高并发执行」拆成两层，让人从「盯着每一步」上移到「决策与验收」。这是整套架构的核心主张：Session 应是实现细节。

设计取舍

  • Router 只分派不干活：常驻单 Session（id 存 KV），刻意不实现细节；「不等结果」写成硬守卫（禁 sleep、禁长等待）
  • Worker 只干活不抢话：每 Ticket 一 Session + 一目录，独立上下文、最强模型，只向 Router 汇报
  • 订阅直通：同一 Thread 的后续事件由程序直发 Worker，不再绕 Router
  • 批量下单：一次 route 带 1–20 条决定；路由备注 ≤30 词，禁止改写需求

↓ 下传（请求）

Assignment（派工）：标题 + ≤1500 字符任务说明 + 源 Trigger 卡 + ≤30 词路由备注 + 执行环境变量（工单目录 / 名称 / id）。

并发默认 3（1–16），另留 1 个槽位专供人的消息；后台作业最多 30 分钟。

↑ 返回（响应）

Report（progress / waiting / ready / blocked / failed / dropped）+ 结构化 Attention（需要人决定的问题）。

越界请求不是硬顶，而是 handback 交回准入层重新分派。

载荷形状 / 锚点 
派工消息 { title, assignment(≤1500 chars), sourceTriggerCard,
           routingNote(≤30 words), env{ DSH_SUPERAGENT_DIR/NAME/TICKET } }

Report   { state, summary(≤600 chars), question? }
Attention{ 结构化字段 → 路由到原始对话，而非写进报告正文 }

L5

领域与调度内核

Engine · Effects · Outbox · Store自治层

自治能成立的地基

作用

保证多会话并发下的一致性、幂等、崩溃可恢复、可审计。没有这一层，「主动」= 重复劳动 + 重复消息。

设计取舍

  • Engine 是唯一写者：所有命令同步、每命令一事务；端口在事务内入队，适配器在提交后执行
  • 先落库后执行：Effects 持久副作用队列，6 种 kind 各有并发上限与退避
  • Outbox 回执：消息「入队」与「回执」同一事务，保证不重不漏
  • 单库 9 表 + 生成列索引：每轮只读「活跃工作」，不扫全表

↓ 下传（请求）

命令：receive / decide / attach / bindThread / assignmentStarted / report / reply / evaluateDue / policyChanged。

调用方只拿到自己角色那一份接口（Sources / MainSession / People / Settings / Executor）。

↑ 返回（响应）

领域事件：trigger.received · eval.started · decision.recorded · ticket.created/ended · assignment.started/ended · policy.changed。

命令返回事务结果；副作用返回 effect 行（kind / key / payload / due）。

载荷形状 / 锚点 
Effect { kind: 'assessment'|'launch'|'delivery'|'relay'|'notice'|'reply',
         key, payload, due, attempts }
// 同一 kind/key 只有一行；重复入队=替换 payload 并立即到期

命令 → 事务提交 → 事件；失败回滚 → 不产生副作用（afterCommit 才执行）

L4

Agent 内核：turn / step

agent-loop · session log · system-prompt底座 DSH

一次输入的排空

作用

把「一次输入」推进成「若干次模型请求 + 工具执行」。这是所有 Agent 产品的最低共同层，也是唯一必须逐字正确的一层。

设计取舍

  • turn ⊃ step：turn = 排空一次输入；step = 一次模型请求 + 其工具；turn 可含 0 个 step
  • 会话日志是唯一真源：「模型可见即已记录」，历史从日志派生
  • 扩展点放事件上：agent/pre-step、agent/request、llm/stream、tools/* 都是 waterfall
  • 连 loop 都可替换：插件依赖 agent，绝不依赖 agent-loop

↓ 下传（请求）

组装后的 messages（系统提示 + 历史 + 新输入）+ 本步工具 schema + 模型选择（快照后冻结）。

请求一旦发出不可变；取消则 system 与 user 都不提交。

↑ 返回（响应）

assistant/message（含 tool calls）或 assistant/attempt（失败尝试）+ tool/result + usage。

全部追加回日志，供下一步派生；压缩只隐藏条目、不删除历史。

载荷形状 / 锚点 
turn/start → [step/start → agent/request → system/message + user/message
              → llm/stream* → assistant/message
              → tool/call* → tool/result*] → step/end
           → agent/turn-stopping → turn/end

L3

工具执行

tool/call → pre-execute → guards → approval → execute → post-execute → tool/result底座 DSH

意图变副作用的地方

作用

把模型的「想调用」变成「真执行」，并且在中间插入权限、沙箱、审批、结果改写——而不改主循环一行。

设计取舍

  • 先记录后执行：tool/call 先进会话日志，崩溃也能知道「它想干什么」
  • 策略插在 seam 上：hook / 权限 / 沙箱走 pre-execute，改策略不用改循环
  • 审批是 fail-closed：一次性询问，缺失或无法回答即拒绝
  • 三段 waterfall：pre / execute / post 都能转换调用，post 还能 replace 或追加 context

↓ 下传（请求）

tool name + 已解析参数（schema 校验后）；可能附带一次「更宽沙箱模式」的重试声明。

↑ 返回（响应）

tool/result：content blocks + isError。被拒绝 / 拒绝审批也走同一条通道返回，模型无法区分「工具不存在」与「被拦」。

载荷形状 / 锚点 
tool/result { content: [ {type:'text'|'image', …} ], isError: boolean }

denied  { reason }            // 与失败结果同一形状，模型无需特殊处理
sandbox denied → "[sandbox: file access denied under workspace-write mode]"
                 + 一次更宽模式重试提示

L2

能力 seam

ctx.llm · ctx.fs · ctx.shell · ctx.sandbox · ctx.skills · ctx.mcpResources …底座 DSH

可替换的能力面

作用

提供「真实能力」，同时把所有能力做成可替换的缝：换模型、换沙箱、换 shell、换持久化后端，都不动上层。

设计取舍

  • 一个 ctx.<key> = 一个 seam：Service Definition + Provider + Consumer 三角色
  • 按 key 查找，不 import 实现：上层不知道底层是谁
  • 注册可逆：ctx.effect() / ctx.on() 返回 disposer，卸载即撤销
  • 作用域两层：全局，或绑定恰好一个 agent scope（不向下继承给 subagent）

↓ 下传（请求）

能力调用：llm.stream、fs.write、shell.exec、tools.register、skills 注入、mcp 调用、jobs / schedule 登记。

↑ 返回（响应）

流式 chunk、写入结果、退出码、分类后的错误（可退避 / 可换模型 / 该压缩 / 别重试）。

技能注入走 user/message 替换，不污染系统提示。

载荷形状 / 锚点 
seam 三角色（以 shell 为例）
  Service Definition : dsh-shell            → ctx.shell
  Provider(s)        : dsh-bash-local | dsh-bash-sandbox
  Consumer           : dsh-tool-bash        （面向模型的工具）

规模：372 个包 · 108 个 ctx.* 服务 · 76 条工具 schema

L1

运行时与外部世界

model API · 执行环境 · 沙箱后端 · 凭据 · 会话文件 · SQLite底座 DSH

真正发生的地方

作用

模型 API、进程、文件系统、持久化。上面七层全部是「组织方式」，只有这一层真的在花钱、真的在改文件。

设计取舍

  • 会话日志用不可变代际：session.vN.jsonl[.zstd]，已提交代际绝不重命名/替换/删除，升级靠逐级迁移包
  • 凭据不落到提示词：走凭据 seam，失败 fail-closed
  • 沙箱 ≠ 安全边界（官方自述）：仍需一性 VM / 容器、最小权限、备份
  • 桌面 = 壳 + 打包运行时：Electron 用 --port 0 起完整 Web 应用，带 token 的 URL

↓ 下传（请求）

HTTP 请求（含流式）、syscall、文件 IO、子进程、持久化写入。

↑ 返回（响应）

token 流与 usage、字节、退出码、持久化事件；错误按可恢复性分类后再上抛。

传递 ↓Input{kind:'trigger'} 投给该 Ticket
返回 ↑只有「没有 owner」的 Trigger 才排队 Eval
人的消息可唤醒 ended 工单；bot/CI 不能
L6
Worker在下次 step 就收到新消息
传递 ↓Input 卡片（≤600 字 + replies_to）
返回 ↑自决：在范围内就干，越界就 handback
L4~L1
执行同一 Session 继续，不新建
传递 ↓本步 messages 里带上新输入
返回 ↑Report；Router 只收到一条 follow_up 通知
链路 4 · 越界交回

Worker 说「这不该我干」

5 跳。它把「分派的错」变成一次新的准入，而不是硬干或沉默。

L6
Workerorchestrator_trigger_handback
传递 ↓triggerId + reason（进 candidate）
返回 ↑{queued: false}：另有主人则不入队
一个 Trigger 只能被交回一次；Subscription 保留
L5
调度内核handback() 记 disposition
传递 ↓等「没有其他 Ticket 拥有它」再排新 Eval
返回 ↑trigger.requeued 事件
回到准入层，用同一条 gate 重新判
L7
事件准入按普通消息重判（candidate 带交回理由）
传递 ↓交回理由进 candidate 卡
返回 ↑accept / attach 到别的工单 / ignore
L6
Router重新分派（禁止 attach 回原工单）
传递 ↓新的 Assignment 或 attach 指令
返回 ↑路由结果
L5
调度内核新 Assignment 起在目标工单
传递 ↓effect: launch / delivery
返回 ↑assignment.started
链路 5 · 崩溃恢复

进程被杀之后，它怎么接上

4 跳。「先落库后执行」在这一刻兑现价值：不重发消息、不丢工单。

L1
运行时进程被杀 / 机器重启
传递 ↓无（此刻只有磁盘上的状态）
返回 ↑会话日志 + SQLite 里已提交的事实
启动：拿目录锁（防双进程）→ 打开 Store → 起 Runtime
L5
调度内核恢复未完成工作
传递 ↓运行中的 Assignment 标 assignmentInterrupted；最旧工单优先
返回 ↑未投递的 Input 重新投递（副本去重）
L6
Router / Worker同一 Session / 目录 / 分支 / PR 上重建
传递 ↓recovery note：先核对目录、git 历史、GitHub，再重做外部动作
返回 ↑新的 Report（不会重复开 PR）
L4+
继续跑turn 接着排空，未读消息在下一 step 被吃进来
传递 ↓messages（从日志重建）
返回 ↑正常结果交付

03边界契约：每一跳到底传什么

这一节是「接口表」。判断一个实现是否符合这套架构，最快的办法是看它的边界是否守住了这几条形状 + 语义。

边界载荷生产者 → 消费者幂等 / 失败语义
L8→L5Trigger（不可变，内容派生 id）Source → Engine同 id 二次到达 = duplicate；未收听 = filtered
L7→L6candidate 卡 + DecisionMasterAssessor → Router候选有超时；未送达 Router 前不计时
L6→L7orchestrator_route：1–20 条决定Router → Engine逐条独立执行，单条被拒不阻塞整批
L7→L5Decision + MandateEval → Engineaccept 按 trigger id 幂等；Mandate 不可变
L5→L6派工消息（标题 + ≤1500 字 + 卡 + ≤30 词备注）DshExecutor → Worker Sessionlaunch 失败 → 工单失败（瞬时失败重试 3 次）
L6→L5Report / Attention / handbackWorker → EngineReport 幂等；handback 每个 Trigger 只一次
L5→L6Input{trigger / policy-changed / resume / text / note}Engine → Worker投递失败 person/delivery 阶段可见，重试到成功
L5→L8reply（回执 / 回答 / 结果 / attention）Outbox → Channel同工单同会话保序；3 次失败成系统问题
L6→L4messages + 工具 schema + 模型选择Sessions → agent-loop请求冻结不可变；取消则都不提交
L4→L3tool/call → args（schema 校验）agent-loop → tools先记录后执行；denied 与失败同形
L3→L2能力调用（ctx.* 方法）tool body → seam注册可逆；错误按可恢复性分类

四个「形状」值得背下来

① 下传永远是「意图 + 依据」Trigger 带 actor 与地址，Assignment 带源 Trigger 卡，tool/call 带 args。上层不替下层做实现，只给意图和判断依据。反例：Router 替 Worker 写实现计划
② 返回永远是「事实 + 状态」Report 是状态机值不是自由文本，tool/result 带 isError，Decision 带原因码。自由文本不能驱动控制流。反例：从 Report 正文推断「在等人」
③ 授权与上下文走不同通道Subscription 直通只给上下文、不给权限；Mandate 只由 accept/stop/revalidate 改变。反例：让「订阅到消息」等于「有权干活」
④ 一切可观察的都要先落库tool/call、Trigger、effect、outbox 回执都先记录再执行；崩溃后能靠日志重建。反例：先发消息再记账

04八条不变量：分层能不能立住看这些

与实现语言无关。换一套代码重写，这些仍然应该成立；破了其中任何一条，分层就会退化成「一堆互相调用的模块」。

1 · 会话日志是唯一真源「模型可见即已记录」：每个模型请求都能从日志重建；压缩只隐藏被取代条目，不删除历史。DSH · packages/core/session
2 · 每类状态只有一个写者Trigger/Ticket/Assignment 只由 Engine 写；回执只由 Outbox 写；健康条目各由唯一 claim 者写。原型 · docs/007-architecture.md:261-271
3 · 先落库后执行命令在事务内入队 effect，提交后才动外部世界；回滚则绝不产生副作用。原型 · src/app/effects.ts
4 · 幂等由内容派生Trigger id = sha256(内容)；accept 按 trigger id 幂等；effect 同 kind/key 只有一行。原型 · src/core/ids.ts
5 · 授权不可伪造Mandate 只有三变；Executor 不能宣称「有人让它停」；stop 必须由 Eval 或面板判定。原型 · docs/002-authorization.md:129
6 · 订阅直通不授权后续事件绕过 gate，但只受既有 Mandate 约束；上下文与权限走不同通道。原型 · docs/002-authorization.md:20-22
7 · 越界必交回，不硬顶Worker 判断超出 Ticket 范围就 handback，等没有 owner 时回 Eval 重新分派。原型 · docs/007-architecture.md:91
8 · 注册是可逆副作用工具、提示词段、适配器、监听器都带 disposer；卸载插件即撤销，不留「删不掉的内核补丁」。DSH · docs/cordis-primer.zh.md
